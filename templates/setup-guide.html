Crows for Foundry · Unofficial

Greetings, Crows and Refs!

Welcome! Before we head into the dungeon, let's get your playtest content into Foundry. There are a couple of steps outside the game, but you don't need to know how to code. :)

The short version

Install Python → unpack your PDFs → run the builder → import in Foundry.

This is a Ref / host setup job. Players don't need Python or their own import.

The item, trait, and bestiary compendiums aren't bundled with the system. The included tools read your copy of the MCDM playtest PDFs to build them. Some rule reminders and fixed tables are included, so keep the books handy too. These are playtest materials, so future packets may need updated tools.

1. Get Python ready

You'll need Python 3.10 or newer on the computer running the builder. Grab a current stable version from python.org and follow its installer. Python is free. You won't be writing any Python yourself!

On Windows, enable Add Python to PATH if your installer offers it. After installing, close and reopen the builder. On Linux, you'll also need Python's venv support; your host can help with that.

2. Find your system folder and your PDFs

Find Foundry's User Data folder, then open Data/systems/fvtt-crows-system. This is where the builder lives. If you're using a hosting service, this folder is on the server: see the hosting note below.

Where is my User Data folder?

On Foundry's Setup screen, open Application Configuration using the cog icon at the top right. Copy the User Data Path, open that folder in your file manager, then go into Data, systems, and fvtt-crows-system. You should see the two builder files there. A managed host may provide its own file manager instead.

Download your playtest packet and extract the ZIP first. Keep the Characters book, Ref book, Inventory Cards, Profession cards, and POI cards together, with one copy of each PDF. Keep the packet's subfolders and original filenames.

Easiest option: no long folder path to type!

Open the included pdfs folder inside fvtt-crows-system and extract your playtest ZIP there. There's a little ADD_PDFS_HERE.txt readme inside to point you in the right direction. The builder searches inside it, including subfolders. When asked for the playtest folder, press Enter.

Want to keep the PDFs somewhere else?

That's fine! Give the builder the folder containing the extracted packet, not the ZIP or an individual PDF.

Windows: open that folder in File Explorer, click the address bar (or press Ctrl + L), and copy the full path. Paste it when the builder asks for the playtest folder. For example: C:\Users\YourName\Downloads\Crows Playtest. Quotes from “Copy as path” are okay.

Linux / macOS: use the folder's full path with --packet. Put quotes around it, especially if it has spaces. The examples below are placeholders: replace them with your actual folder.

3. Run the builder

Choose the computer you're building on. The first run downloads a few helper libraries, so it needs an internet connection. Let it finish; the progress messages will tell you what it's doing.

Windows

In the system folder, double-click build_playtest_content.cmd. Paste your PDF folder when asked, or press Enter for the pdfs folder. The launcher handles the helper libraries for you.

Linux / macOS

Open a terminal in the system folder and run:

sh build_playtest_content.sh --setup --interactive

Paste your PDF folder at the prompt, or press Enter for pdfs. For a server or an explicit folder path, use:

sh build_playtest_content.sh --setup --packet "/path/to/Crows Playtest"

On later runs, you can leave out --setup.

Using a hosting service or another computer?

A folder on your desktop isn't a folder on your server. Run the builder where the PDFs actually are. If your host supports Python, use the server's system folder and a PDF folder on that server.

Otherwise, build locally using a copy of this system, then upload the generated packs/*.json files and assets/monsters/ folder to the same locations in the hosted system. Keep their folder structure. You don't need to upload Python or tools/.venv. Your host's file manager or support team can help.

4. Bring it into Foundry

Once the build succeeds, join your world as the Ref (GM). Open Settings → Configure Settings → Crows (Unofficial) → Import Playtest Content, or use the button below. Click Re-check files, then Import everything found.

Your equipment, dungeon loot, traits, and bestiary will appear in the Compendium Packs tab. That's it! You can start making Crows. Re-importing preserves local edits and doesn't delete entries; check the report for anything it kept for review.

Something didn't work?
  • Python wasn't found: finish installing Python, then reopen the launcher. On Windows, try py --version or python --version in a new terminal; on Linux/macOS, try python3 --version.
  • Folder or PDF not found: check that you extracted the ZIP and chose the packet folder. Compare the folder printed by the builder with the one you meant to use.
  • More than one matching PDF: keep old packets and duplicate downloads outside your chosen folder.
  • Missing libraries or venv: use the first-run command with --setup; on Linux, ask your host to install Python's venv support.
  • Foundry says “Not built”: check that the builder finished successfully and that the files are in the system folder used by your Foundry server. Then click Re-check files.

Still stuck? Include the error message and what step you reached when reporting an issue. If extraction started, its log is in tools/out/build.log.

Ready for the rest?

Foundry helps with rolls, slots, and resource tracking. You and the Ref still handle most trait effects, spell effects, ammunition spending, and downtime. A button does its named action; it doesn't resolve every rule around it. The play guide explains what's automatic and what's manual.

The full docs on GitHub cover character creation, item management, permissions, villages, and more. Please give it a try and let me know how it goes. ^_^

Reopen this guide anytime from Settings → Configure Settings → Crows (Unofficial) → Start Here. Closing it stops the automatic welcome for your user in this world.
